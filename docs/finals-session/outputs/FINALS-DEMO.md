## What was validated

The initial validation exported three signed passes and one honest partial result. Its final pass
was generated by a fresh runner after an actual EC2 restart. All four initial signatures
verified offline, all four altered-byte checks failed, and no runner registration
or ephemeral Kubernetes namespace remained after completion. S3 denied reader
writes and writer deletes; container access to instance metadata was blocked.

The newer controlled experiments, including a signed cleanup failure, are recorded in [CONTROLLED-EXPERIMENTS.md](CONTROLLED-EXPERIMENTS.md).

## Cost and stopping

This is **credit-funded EC2, not permanently free hosting and not Firecracker**.
The checked Free plan had $94.74 remaining credits and 122 days. Usage reports
can lag; an unchanged displayed balance does not mean the deployment incurred
no usage. Compute plus IPv4 is approximately $0.10076 per running hour, plus
40 GiB storage, S3 and KMS. See the full guide for rates and sources.

The host has an eight-hour stop timer after each boot. At handoff, the latest
boot was 10:34:38 UTC on 8 September, so the scheduled stop is approximately
**12:04 AM India time on 9 September**. A later boot starts a new eight-hour interval.
Stop it sooner after the demo, once the current receipt has arrived:

```bash
bash work/aws.sh ec2 stop-instances --instance-ids i-0f21b25d3a04d8541
bash work/aws.sh ec2 wait instance-stopped --instance-ids i-0f21b25d3a04d8541
```

Close the bridge and tunnels. Stopping releases the automatic public IPv4 and
stops compute charges; EBS, S3 and KMS remain. Permanent teardown is implemented
in `scripts/aws/teardown.py`, defaults to read-only, and takes the saved
[AWS resource manifest](aws-resources.json). Export metadata before deleting the
host. Follow the [staged teardown checklist](ephemeral-runner-cleanup-receipt-aws/docs/aws-finals.md#stop-resume-and-teardown).
Evidence has **eight-day Compliance Object Lock by default** and cannot be
deleted early, including by root. The evidence bucket and KMS key are deliberately
retained when the compute stack is deleted.

## Say this to the judges

“GitHub schedules a real single-job runner in Kubernetes on AWS EC2. An external
observer checks cleanup, a separate finalizer signs the observations through our
private Sigstore services, and an independent API verifies them. Amazon S3 with
KMS encryption, versioning and Object Lock replaces our local MinIO service.”

“This deployment does not run Firecracker. EC2 preserves the host-level access
our observer needs. We use temporary AWS Free-plan credits, and we distinguish
container isolation from a separate microVM. The signature binds evidence of
defined cleanup checks; it does not prove physical erasure or protect against a
malicious host administrator.”

“The GitHub administration credential stays on my laptop. A restricted bridge
over AWS Systems Manager handles registration and GitHub metadata. The runner,
observer, signing services, archive and metadata run in AWS.”
